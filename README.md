# 5th SENSE Perfume Bar

Est. 2025.

Интернет-магазин парфюмерного бутика **5th SENSE**.

Визуальный язык построен по вывеске бутика (фото `assets/img/brand-sign.jpg`, сейчас на сайте не показывается):
тёплый ivory камня, глубокий чёрный и сдержанное матовое золото в акцентах,
мягкий боковой свет. Флаконы стоят на «стене» из тёплого камня, логотип
5TH SENSE набран шрифтом DM Serif Display во всю ширину экрана, заголовки —
DM Serif Display (русские буквы — Playfair Display), текст — Onest. Цвета заданы токенами
в начале `assets/css/style.css` (`--ink`, `--paper`, `--gold`, `--gold-soft`,
`--gold-deep`); неоновых, кислотных и насыщенных цветов нет.

Движение: вступительная заставка с эмблемой, сцены, привязанные к прокрутке
(текст истории проявляется по словам, индекс
ароматов меняет картинку и номер, горизонтальная лента бестселлеров),
появление элементов при прокрутке, курсор «Смотреть», шторка между страницами.
Всё отключается при `prefers-reduced-motion`.

## Что есть

- **Главная**: герой со сменой флаконов и логотипом во всю ширину, история бренда,
  индекс избранных ароматов, лента бестселлеров, семейства ароматов, новинки, консультация.
- **Каталог**: поиск (по названию, бренду и нотам), фильтры (семейство, пол, цена, бренд,
  наличие), сортировка, активные фильтры чипами, пустые состояния.
- **Страница аромата**: большое фото с проявлением при открытии и увеличением под курсором, объёмы и цены,
  наличие, количество, «Добавить в корзину», «Купить сейчас», описание, пирамида нот,
  семейство, стойкость, шлейф, блок «С чем сочетается этот аромат».
- **Корзина**: выезжающая панель, изменение количества с учётом остатка, удаление с
  возможностью вернуть, прогресс до бесплатной доставки, итог.
- **Оформление заказа**: покупатель, доставка, оплата, комментарий, валидация, итог
  заказа, подтверждение. Черновик формы сохраняется.
- **Избранное**, **Доставка и оплата**, страница 404.
- **Юридические страницы (черновики)**: публичная оферта (`#offer`), политика конфиденциальности (`#privacy`), возврат и обмен (`#returns`). Согласие с офертой и обработкой данных обязательно при оформлении заказа и сохраняется в заказе. Реквизиты продавца — в `FS.config.seller` (`assets/js/config.js`); значения в квадратных скобках подсвечиваются на страницах как незаполненные. Перед запуском тексты нужно проверить у юриста.
- **Заказы на сервере и уведомления в Telegram** (на Vercel, см. ниже).
- **Админ-панель** (`#admin`, ссылка «Вход для сотрудников» в подвале): обзор, заказы
  со статусами и оплатой, товары с редактированием цен, остатков, описаний и фото,
  добавление и удаление товаров, экспорт, импорт и сброс каталога.
- Адаптив от 360 px до широких мониторов, клавиатурная навигация,
  `prefers-reduced-motion`, структурированные данные schema.org (Store, ItemList, Product).

## Запуск

Сборка не нужна: это статический сайт.

```bash
python3 -m http.server 8000
# открыть http://localhost:8000
```

Подходит любой статический хостинг (GitHub Pages, Netlify, Vercel, Nginx).
Приём заказов на сервере и уведомления в Telegram работают на Vercel; на других
хостингах и при локальном просмотре сайт работает в демо-режиме.

### Выкладка на Vercel

Настройки в `vercel.json`: при выкладке скрипт `scripts/export-site.mjs`
пересобирает `sw.js` и складывает файлы сайта в папку `public/` (служебные
файлы проекта туда не попадают), заголовки для приложения уже прописаны.

**Через GitHub, с автообновлением.** На vercel.com: Add New → Project →
Import Git Repository → `perfume-shop-5th-sense` → Deploy. Framework Preset
оставьте «Other», остальные поля Vercel возьмёт из `vercel.json`. Выкладывается
основная ветка (`main`); чтобы выложить эту версию до слияния, в настройках
проекта Settings → Git → Production Branch укажите ветку с ней.

**С компьютера, без GitHub.** В папке проекта выполните `npx vercel --prod`
(понадобится Node.js); при первом запуске Vercel попросит войти и задаст пару
вопросов — ответы по умолчанию подходят.

### Выкладка на Netlify

В проекте уже есть настройки: `netlify.toml` (при выкладке пересобирается `sw.js`),
`_headers` (заголовки для сервис-воркера и манифеста) и `_redirects`
(служебные файлы не отдаются посетителям).

**Через GitHub, с автообновлением.** На app.netlify.com: Add new site →
Import an existing project → GitHub → репозиторий `perfume-shop-5th-sense`.
Branch to deploy — ветка с этой версией сайта (или `main` после слияния);
остальные поля Netlify возьмёт из `netlify.toml`. После этого каждое изменение
в ветке выкладывается само.

**Без GitHub, перетаскиванием.** Соберите папку с `index.html`,
`manifest.webmanifest`, `sw.js`, `_headers`, `_redirects` и `assets/`, сожмите
в zip и перетащите на app.netlify.com/drop. Обновлять сайт так нужно вручную,
перед этим выполнив `node scripts/build-sw.mjs`.
Маршруты — якоря (`#catalog-men`, `#product-aventus`), поэтому настройка сервера
не требуется.

Сборка в один HTML-файл (для Artifact или отправки одним файлом):

```bash
node scripts/build-single.mjs   # → dist/5th-sense.html
```

## Приложение на телефоне (PWA)

Сайт устанавливается на главный экран телефона как приложение: своя иконка
(логотип 5th SENSE), запуск на весь экран без строки браузера, работа без
интернета (каталог, фото и шрифты сохраняются на телефоне после первого открытия).

- **Android (Chrome)**: пункт «Установить приложение» в меню и подвале или
  системное окно установки. Один раз на телефоне сайт сам предлагает установку.
- **iPhone (Safari)**: «Поделиться» → «На экран „Домой“»; кнопка
  «Установить приложение» показывает эту подсказку.

Файлы: `manifest.webmanifest` (название, цвета, иконки, ярлыки «Каталог»,
«Избранное», «Корзина»), `assets/icons/` (иконки), `assets/js/pwa.js`
(регистрация и установка), `sw.js` (офлайн-кэш).

Важно:

- приложение устанавливается только с сайта на **https** (или с `localhost`
  при разработке): подойдёт любой хостинг с SSL, например GitHub Pages, Netlify, Vercel;
- `sw.js` собирается скриптом — **после любых изменений файлов сайта** выполните
  `node scripts/build-sw.mjs`, иначе у установивших приложение останется старая версия;
- заказы и избранное, как и на сайте, пока хранятся на телефоне покупателя,
  до подключения сервера.

## Перед запуском в продажу

1. **Контакты** — замените телефон, почту и адрес в `assets/js/config.js`.
2. **Фотографии** — лежат в `assets/products/`, товар ссылается на фото полем
   `image`. Без фото показывается чертёж флакона.
3. **Цены, остатки и ноты** — в `assets/js/data.js`. Цены в тенге указаны
   ориентировочно, ноты взяты из открытых описаний ароматов: их нужно сверить.

## Заказы на сервере и уведомления в Telegram

На Vercel вместе с сайтом работают серверные функции из папки `api/`
(общий код в `server/`, внешних зависимостей нет):

| Адрес | Назначение |
|---|---|
| `GET /api/status` | что подключено: хранилище, Telegram, пароль админки |
| `POST /api/orders` | оформление заказа с сайта |
| `GET`, `PATCH`, `DELETE /api/orders` | список заказов, смена статуса, удаление (админка, нужен пароль) |
| `GET`, `POST /api/telegram` | настройка бота из админки (нужен пароль) |
| `GET /api/products` | каталог (или `null`, если он ещё в `data.js`) |
| `PUT`, `PATCH`, `DELETE`, `POST /api/products` | загрузка таблицы, правка, удаление товара, сброс (нужен пароль) |
| `GET`, `POST /api/image` | фото товаров, загруженные в админке |
| `POST /api/bot` | сообщения боту от Telegram (webhook, проверяется секретом) |

Сервер сам пересчитывает цены, суммы и доставку по `assets/js/data.js` и
`config.js`, поэтому подменить цену из браузера нельзя. Заказ сохраняется в
хранилище и сразу приходит сообщением в Telegram; номера идут по порядку
(`5S-1001`, `5S-1002`, …). С одного адреса принимается не больше 8 заказов
за 10 минут, а скрытое поле в форме отсеивает ботов.

### Настройка (один раз, на vercel.com)

1. **Хранилище.** Проект → Storage → Create Database → **Upstash for Redis**
   (бесплатного тарифа хватает) → Connect to project. Переменные
   `KV_REST_API_URL` и `KV_REST_API_TOKEN` Vercel добавит сам.
2. **Бот.** В Telegram откройте @BotFather → `/newbot` → придумайте имя и адрес
   бота. BotFather пришлёт токен вида `123456:ABC…`.
3. **Переменные.** Проект → Settings → Environment Variables:
   - `ADMIN_PASSWORD` — пароль для входа в админ-панель;
   - `TELEGRAM_BOT_TOKEN` — токен бота.
4. **Redeploy.** Deployments → у последней выкладки «…» → Redeploy.
   Переменные начинают действовать только после новой выкладки.
5. **Бот для покупателей.** На сайте: `#admin` → вход → вкладка «Данные» →
   «Включить бота». Сайт сам настроит бота: адрес для сообщений (webhook),
   меню команд и кнопку «Магазин».
6. **Сотрудники.** Там же «Подключить сотрудника»: появится одноразовая ссылка
   (15 минут). Откройте её на телефоне сотрудника и нажмите «Старт» или
   добавьте бота в общую группу по второй ссылке.

### Что умеет бот

- **Меню** по «Старт»: открыть магазин, мои заказы, консультация, контакты.
- **Магазин внутри Telegram.** Кнопка «Магазин» открывает сайт прямо в
  Telegram (мини-приложение, `assets/js/telegram.js`). Имя подставляется в
  форму заказа, а заказ сразу привязывается к чату покупателя: сервер
  проверяет подпись Telegram.
- **Статусы заказа.** На странице «Заказ принят» есть ссылка «Следить за
  заказом в Telegram». Когда в админке меняется статус или отмечается оплата,
  покупатель получает сообщение. Ссылка у каждого заказа своя, чужой заказ по
  номеру узнать нельзя.
- **Консультация.** Любое сообщение покупателя бот пересылает сотрудникам,
  и Telegram сразу открывает режим ответа на него. Сотрудник просто пишет
  текст, бот пересылает его покупателю от имени магазина и подтверждает
  «✓ Отправлено покупателю …». Обычное сообщение сотрудника в личном чате с
  ботом уходит автору последнего вопроса (за 12 часов); на более старый
  вопрос отвечают через «Ответить». В группе сотрудников — только через «Ответить».
- Сотрудниками считаются только чаты, подключённые по ссылке из админки
  (или указанные в `TELEGRAM_CHAT_ID`), поэтому заказы с телефонами не
  попадут к покупателям.

Вместо шага 6 можно указать ID чатов сотрудников через запятую в переменной `TELEGRAM_CHAT_ID`.

Работает и частичная настройка: без хранилища заказы только приходят в
Telegram (в админке их не видно), без бота — только сохраняются. Пока не
подключено ни то ни другое (и при локальном просмотре, и в сборке в один
файл), сайт работает в демо-режиме: заказ сохраняется в браузере покупателя,
о чём говорит страница подтверждения.

Каталог по-прежнему хранится в `data.js`: правки товаров в админке видны только
в браузере, где их сделали. Чтобы изменить каталог для всех, перенесите
экспорт из вкладки «Данные» в `data.js`. Остатки на сервере не списываются.

## Подключение оплаты

Сейчас **реальные платежи не подключены**. В оформлении доступна только оплата при
получении, а способ «Онлайн картой» показан неактивным с пометкой. На странице
подтверждения в демо-режиме сказано, что заказ сохранён только в браузере.

Чтобы подключить провайдера (Kaspi Pay, CloudPayments, Stripe и т. п.):

```js
FS.payments.register('online_card', {
  async start(order) {
    const res = await fetch('/api/payments', { method: 'POST', body: JSON.stringify({ orderId: order.number }) });
    const { redirectUrl } = await res.json();
    location.href = redirectUrl; // страница оплаты провайдера
  }
});
```

и включите способ в `FS.paymentMethods` (`enabled: true`). Подтверждение оплаты
должен принимать сервер (webhook провайдера), а не браузер.

## Подключение доставки

Способы доставки задаются в `FS.delivery` (`config.js`). Функция `price(subtotal)`
возвращает стоимость или `null`, если её подтверждает менеджер. Для расчёта через
службу доставки замените её на запрос к API службы и используйте `FS.shipping.quote`.

## Каталог из таблицы (сотни товаров)

Каталог ведётся в Excel. Шаблон: `assets/files/5th-sense-catalog.xlsx` (в админке
ссылка «Шаблон таблицы»), в нём уже стоят текущие ароматы и инструкция.

- **Одна строка — один объём аромата.** Строки с одинаковым артикулом (или
  брендом, названием и концентрацией) собираются в один товар с несколькими
  объёмами.
- **Админка → «Товары» → «Загрузить таблицу».** Сайт покажет, сколько товаров
  добавится, изменится и пропадёт, и ошибки с номерами строк. Каталог
  обновляется только после «Применить».
- **«Скачать таблицу»** выгружает текущий каталог в том же формате: удобно
  поменять цены или остатки и загрузить обратно.
- **«Загрузить фото»** принимает сразу много файлов. Фото подключается к
  товару по колонке «Фото» (расширение не важно: `oud.jpg` в таблице подойдёт
  к файлу `oud.png`) или по артикулу. Фото сжимаются в браузере до 1200 px и
  хранятся в Upstash Redis, отдаются через `/api/image` с долгим кэшем.

С сервером каталог хранится в Redis (`/api/products`) и сразу виден всем
покупателям; сервер ведёт остатки: заказ списывает, отмена в админке
возвращает, а купить больше остатка нельзя. Пока каталог ни разу не загружали,
источник — `assets/js/data.js`; «Данные» → «Вернуть исходный каталог»
возвращает к нему. Без сервера загрузка таблицы меняет каталог только в этом
браузере (как раньше).

Сайт рассчитан на большой каталог: карточки показываются по 24 с кнопкой
«Показать ещё», в фильтре брендов есть поиск, последняя копия каталога
хранится в браузере (сайт открывается сразу, обновление приходит в фоне), а
фото товаров не скачиваются при установке приложения, только по мере просмотра.

## Админ-панель

Откройте `#admin` (или «Вход для сотрудников» в подвале).

**С сервером** (задан `ADMIN_PASSWORD`) пароль проверяет сервер, заказы
загружаются из хранилища и видны с любого устройства, список обновляется
раз в минуту, смена статуса сохраняется на сервере. Вкладка «Данные»
показывает, подключён ли бот, и позволяет подключить чат Telegram.

**Без сервера** админка работает в демо-режиме, пароль `5thsense`:

- каталог и заказы хранятся в `localStorage` браузера, где их изменили;
  другие посетители этих изменений не видят;
- пароль ничего не защищает: код и данные статического сайта доступны всем;
- заказ с сайта списывает остаток, отмена заказа в админке возвращает его.

Статусы заказа: `status` new → confirmed → shipped → done (или cancelled),
`paymentStatus` unpaid → paid. Заказ содержит покупателя, позиции с ценами,
доставку, оплату, согласие с офертой и итоги.
