# 5th SENSE Perfumery

Интернет-магазин парфюмерного бутика **5th SENSE**.

Визуальный язык построен по вывеске бутика (`assets/img/brand-sign.jpg`):
тёплый ivory камня, глубокий чёрный и сдержанное матовое золото в акцентах,
мягкий боковой свет. Флаконы стоят на «стене» из тёплого камня, логотип
5TH SENSE набран римскими капителями (Cinzel) во всю ширину экрана, заголовки —
классической антиквой Cormorant Garamond, текст — Onest. Цвета заданы токенами
в начале `assets/css/style.css` (`--ink`, `--paper`, `--gold`, `--gold-soft`,
`--gold-deep`); неоновых, кислотных и насыщенных цветов нет.

Движение: вступительная заставка с эмблемой, сцены, привязанные к прокрутке
(кадр героя сжимается в рамку, текст истории проявляется по словам, индекс
ароматов меняет картинку и номер, горизонтальная лента бестселлеров),
появление элементов при прокрутке, курсор «Смотреть», шторка между страницами.
Всё отключается при `prefers-reduced-motion`.

## Что есть

- **Главная**: герой со сменой флаконов и логотипом во всю ширину, история бренда,
  индекс избранных ароматов, лента бестселлеров, семейства ароматов с превью
  у курсора, новинки, консультация.
- **Каталог**: поиск (по названию, бренду и нотам), фильтры (семейство, пол, цена, бренд,
  наличие), сортировка, активные фильтры чипами, пустые состояния.
- **Страница аромата**: большое фото с проявлением при открытии, крупный план, увеличение под курсором, объёмы и цены,
  наличие, количество, «Добавить в корзину», «Купить сейчас», описание, пирамида нот,
  семейство, стойкость, шлейф, блок «С чем сочетается этот аромат».
- **Корзина**: выезжающая панель, изменение количества с учётом остатка, удаление с
  возможностью вернуть, прогресс до бесплатной доставки, итог.
- **Оформление заказа**: покупатель, доставка, оплата, комментарий, валидация, итог
  заказа, подтверждение. Черновик формы сохраняется.
- **Избранное**, **Доставка и оплата**, страница 404.
- **Демо-админка** (`#admin`, ссылка «Вход для сотрудников» в подвале): обзор, заказы
  со статусами и оплатой, товары с редактированием цен, остатков, описаний и фото,
  добавление и удаление товаров, экспорт, импорт и сброс каталога.
- Адаптив от 360 px до широких мониторов, клавиатурная навигация,
  `prefers-reduced-motion`, структурированные данные schema.org (Store, ItemList, Product).

## Запуск

Сборка не нужна: это статический сайт.

```bash
python3 -m http.server 8000
# открыть http://localhost:8000
```

Подходит любой статический хостинг (GitHub Pages, Netlify, Vercel, Nginx).
Маршруты — якоря (`#catalog-men`, `#product-aventus`), поэтому настройка сервера
не требуется.

Сборка в один HTML-файл (для Artifact или отправки одним файлом):

```bash
node scripts/build-single.mjs   # → dist/5th-sense.html
```

## Структура

```
index.html                 оболочка страницы
assets/css/style.css       визуальный язык: токены, материалы, все компоненты
assets/img/                фото вывески бутика, текстуры (SVG), favicon
assets/products/           фото товаров, имя файла = id товара
assets/js/config.js        контакты, валюта, способы доставки и оплаты
assets/js/data.js          категории, семейства, товары
assets/js/bottle.js        флаконы: чертёж, силуэт и объёмная иллюстрация (пока нет фото)
assets/js/store.js         корзина и избранное (localStorage)
assets/js/api.js           слой данных: каталог, заказы, платежи, доставка
assets/js/ui.js            шапка, подвал, карточки, корзина, поиск, уведомления
assets/js/views/*.js       страницы: главная, каталог, товар, оформление, информация, админка
assets/js/motion.js        анимации: сцены прокрутки, появление, курсор, заставка
assets/js/app.js           маршрутизация и переходы между страницами
scripts/build-single.mjs   сборка в один файл
```

Интерфейс получает данные только через `FS.api`, `FS.payments` и `FS.shipping`.
Это единственные места, которые нужно менять при подключении сервера.

## Перед запуском в продажу

1. **Контакты** — замените телефон, почту и адрес в `assets/js/config.js`.
2. **Фотографии** — лежат в `assets/products/`, товар ссылается на фото полем
   `image`. Без фото показывается чертёж флакона.
3. **Цены, остатки и ноты** — в `assets/js/data.js`. Цены в тенге указаны
   ориентировочно, ноты взяты из открытых описаний ароматов: их нужно сверить.

## Подключение базы данных

Формат товара описан в начале `assets/js/data.js`. Сервер должен отдавать те же поля:

| Метод | Назначение |
|---|---|
| `GET /api/products` | список товаров (`FS.api.products(query)`) |
| `GET /api/products/:id` | товар (`FS.api.product(id)`) |
| `POST /api/orders` | создание заказа (`FS.api.createOrder(order)`) |

Загрузите каталог при старте (например, `FS.products = await fetch('/api/products').then(r => r.json())`
перед `FS.app.start()`) и замените тело `createOrder` в `api.js` на `POST /api/orders`.
После этого выключите `demoMode` в `config.js`.

## Подключение оплаты

Сейчас **реальные платежи не подключены**. В оформлении доступна только оплата при
получении, а способ «Онлайн картой» показан неактивным с пометкой. На странице
подтверждения в демо-режиме сказано, что заказ сохранён только в браузере.

Чтобы подключить провайдера (Kaspi Pay, CloudPayments, Stripe и т. п.):

```js
FS.payments.register('online_card', {
  async start(order) {
    const res = await fetch('/api/payments', { method: 'POST', body: JSON.stringify({ orderId: order.number }) });
    const { redirectUrl } = await res.json();
    location.href = redirectUrl; // страница оплаты провайдера
  }
});
```

и включите способ в `FS.paymentMethods` (`enabled: true`). Подтверждение оплаты
должен принимать сервер (webhook провайдера), а не браузер.

## Подключение доставки

Способы доставки задаются в `FS.delivery` (`config.js`). Функция `price(subtotal)`
возвращает стоимость или `null`, если её подтверждает менеджер. Для расчёта через
службу доставки замените её на запрос к API службы и используйте `FS.shipping.quote`.

## Демо-админка

Откройте `#admin` (или «Вход для сотрудников» в подвале). Демо-пароль: `5thsense`.

Админка работает без сервера, поэтому:

- каталог и заказы хранятся в `localStorage` браузера, где их изменили;
  другие посетители этих изменений не видят;
- пароль ничего не защищает: код и данные статического сайта доступны всем;
- заказ с сайта списывает остаток, отмена заказа в админке возвращает его.

Для настоящей работы нужен сервер. Админка уже ходит в данные только через
`FS.api` (`upsertProduct`, `deleteProduct`, `replaceCatalog`, `updateOrder`),
поэтому при подключении сервера меняется только `api.js`.

## Админ-панель на сервере

Админ-панель удобно строить поверх тех же эндпоинтов: CRUD для `/api/products`
(поля из `data.js`, включая `volumes[].stock`), список и статусы `/api/orders`
(`status`: new → confirmed → shipped → done; `paymentStatus`: unpaid → paid).
Заказ уже содержит покупателя, позиции с ценами, доставку, оплату и итоги.
