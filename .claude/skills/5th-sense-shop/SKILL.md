# 5th SENSE Perfume Bar — как работать с этим проектом

Демо-магазин превратился в настоящий: сайт, сервер на Vercel, база Upstash Redis,
Telegram-бот для покупателей и сотрудников, каталог из Excel. Этот файл —
выжимка того, как он устроен и как с ним работать, чтобы не повторять ошибок.

Подробности по темам лежат рядом (читай по необходимости):
- `references/architecture.md` — файлы, маршруты, слой данных `FS.*`, сборка.
- `references/server.md` — API, ключи Redis, переменные окружения, бот, каталог, остатки.
- `references/design.md` — палитра, шрифты, компоненты, что пользователь просил убрать.
- `references/testing.md` — как проверять: тестовый сервер-имитация, Playwright, ловушки окружения.
- `scripts/devserver.cjs`, `scripts/fontroute.mjs` — готовые инструменты для проверки.

## Кто владелец и как с ним говорить

- Владелец — ИП в Казахстане, не программист. Пишет по-русски, часто голосом,
  с опечатками распознавания («пуверквест» = pull request, «Версал» = Vercel).
  Отвечай по-русски, простыми словами, без жаргона; если без термина нельзя —
  поясни его в скобках.
- Для любых действий у него на стороне (Vercel, Telegram, Excel, админка) давай
  нумерованные шаги с точными названиями кнопок. Он ни разу не работал с Excel.
- Он присылает скриншоты с телефона (Android, иногда тёмная тема) — внимательно
  смотри, что на них на самом деле: не раз причина была не там, где он думал.
- Никогда не проси прислать пароли, токены, коды из SMS или данные карт. ИИН и
  номер счёта ИП — не секрет (они печатаются в оферте).

## Как вносятся изменения (важно)

1. Работа идёт в ветке, указанной в задаче (раньше — `claude/wonderful-galileo-2qb0ik`).
   Если PR этой ветки уже смерджен, начни ветку заново от свежего `main`:
   `git fetch origin main && git checkout -B <ветка> origin/main`.
2. После правок: пересобери `sw.js` (`node scripts/build-sw.mjs`) — иначе
   установленное приложение не увидит обновления; при правках сайта полезно
   пересобрать и однофайловую версию (`node scripts/build-single.mjs`).
3. Проверь (см. «Проверка» ниже), закоммить, запушь.
4. PR создавай только когда владелец просит. Он всегда отвечает «да, создай PR»,
   поэтому в конце работы спроси одной строкой «Создать PR?».
5. Владелец мерджит сам → Vercel выкладывает `main` за 1–2 минуты. Предпросмотр
   PR появляется в комментарии бота Vercel (статус Ready) — проси дождаться его.
6. Переменные окружения начинают работать только после новой выкладки (Redeploy
   или мердж). Если владелец задал их до мерджа — Redeploy не нужен.

## Бренд — нерушимые правила

- Название пишется только **5th SENSE** (локап «5th SENSE Perfume Bar, Est. 2025»).
  Никогда «Five Sense», «5 Sense», «5TH Sense».
- Стиль — бутик по вывеске: тёплый айвори, глубокий чёрный, матовое золото.
  Никакого неона, синего, фиолетового, кислотных цветов, дешёвых золотых градиентов
  и «SaaS-вида».
- Действия — подчёркнутые текстовые ссылки (`.line-link`, `.hero-link`), а не
  кнопки-прямоугольники; это касается и админки (`.btn` там переопределён в линию).
- Цены на карточках каталога не показываются (только на странице товара и в корзине).
- Фото флаконов «вплавлены» в фон (`mix-blend-mode: multiply`) и должны целиком
  помещаться в рамку. Поэтому сайт объявлен строго светлым
  (`color-scheme: only light` + meta) — иначе Android в тёмной теме чернит фото.
- Логотип-капсула (`assets/img/logo-intro.png`) — в заставке, на шторке переходов,
  в центре шапки и в подвале (небольшой).
- Детали палитры, шрифтов и компонентов — `references/design.md`.

## Устройство в двух словах

- Статический SPA без фреймворка, маршруты-якоря (`#catalog`, `#product-<id>`,
  `#admin-products`…), общий объект `window.FS`. Данные идут только через
  `FS.api` / `FS.catalog` / `FS.backend` (`assets/js/api.js`).
- Сервер — функции Vercel в `api/*.js` (CommonJS, без зависимостей), общий код в
  `server/*.js`. База — Upstash Redis через REST. Сайт сам определяет режим:
  если `/api/status` не отвечает (локально, Netlify, однофайловая сборка) —
  работает демо-режим в браузере.
- Цены, суммы и доставку сервер **всегда пересчитывает сам** по каталогу —
  данным из браузера не доверяем. Когда каталог на сервере, сервер ведёт остатки.
- Один Telegram-бот для покупателей (меню, мини-приложение «Магазин», статусы
  заказов, консультации) и сотрудников (уведомления, ответы покупателям).
- Каталог на 300+ товаров ведётся в Excel: шаблон `assets/files/5th-sense-catalog.xlsx`,
  загрузка в админке → предпросмотр → «Применить».
- Подробно: `references/architecture.md` и `references/server.md`.

## Проверка перед пушем

Проверяй в браузере, а не «на глаз по коду» — почти все найденные ошибки были
видны только в реальном сценарии.
- Сценарии сайта: главная → каталог → товар → корзина → оформление (и с самовывозом,
  и с курьером!) → «Заказ принят»; админка; мобильная ширина 390 px; нет
  горизонтальной прокрутки и ошибок в консоли.
- Сервер, бот, каталог — на имитации Vercel: `scripts/devserver.cjs` подменяет
  Redis и Telegram в памяти (режимы full / tg-only / none). Как запускать и что
  проверять — `references/testing.md`.
- После проверки честно скажи владельцу, что проверено на имитации, а что
  станет известно только на его настоящем Vercel/Telegram.

## Ошибки, которые уже случались (не повторяй)

- Сервер требовал город при самовывозе, а форма его скрывает → все заказы с
  самовывозом отклонялись. Любое поле, которое форма прячет, сервер не должен требовать.
- `const bot = …` внутри обработчика затенял импорт `bot` → «bot.newToken is not a function».
  Модули импортируй под однозначными именами (`botApi`).
- Сотрудник отвечал боту обычным сообщением, а не «Ответить» → ответ терялся.
  Теперь вопрос приходит с `force_reply`, обычное сообщение уходит последнему
  спросившему (12 ч), бот подтверждает «✓ Отправлено покупателю …».
- Кнопка «Подключить чат» через getUpdates подключала всех писавших боту — риск
  утечки заказов покупателям. Сотрудники подключаются только по одноразовой ссылке.
- Принудительная тёмная тема Android чернила фото → `color-scheme: only light`.
- Хэш мини-приложения `#tgWebAppData=…` ломал маршрутизатор → `assets/js/telegram.js`
  забирает данные и чистит адрес до запуска роутера.
- Неизменённые товары в таблице помечались «изменятся» из-за поля `photo` →
  сравнение идёт по имени файла фото.
- Ещё: в предыдущих PR я путал, в какой PR уходят правки после мерджа — всегда
  проверяй состояние PR перед тем, как сказать «изменения в PR №…».

## Что ещё не сделано (на момент создания навыка)

- Онлайн-оплата: план готов (Kaspi / Halyk ePay / FreedomPay / CloudPayments —
  ждём выбор и тестовые ключи). Нужно: создание платежа на сервере, webhook с
  проверкой подписи, статус «Ожидает оплаты», страницы успеха/ошибки; для
  «Доставки по стране» (цена = null) — только оплата при получении.
- Реквизиты продавца в `assets/js/config.js` (`seller`) — заглушки в квадратных
  скобках; владелец должен прислать: название ИП, ИИН, юр. адрес, банк, ИИК, БИК,
  контакты. Банковские реквизиты в оферту ещё не добавлены.
- Таблица на ~300 ароматов: владелец пришлёт список брендов (или «предложи свой»)
  и, возможно, прайс поставщика. Цены не выдумывать: пустые — подсветить, остаток 0.
