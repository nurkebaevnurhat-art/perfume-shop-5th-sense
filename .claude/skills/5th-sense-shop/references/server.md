# Сервер 5th SENSE (Vercel Functions + Upstash Redis + Telegram)

## Переменные окружения (Vercel → Settings → Environment Variables)

| Переменная | Что это |
|---|---|
| `KV_REST_API_URL`, `KV_REST_API_TOKEN` | Upstash Redis (Vercel добавляет сам при подключении Storage → Upstash for Redis). Поддерживаются и `UPSTASH_REDIS_REST_*`, и варианты с префиксом |
| `ADMIN_PASSWORD` | пароль админки; без него админка в демо-режиме |
| `TELEGRAM_BOT_TOKEN` | токен бота от @BotFather |
| `TELEGRAM_CHAT_ID` | необязательно: ID чатов сотрудников через запятую (иначе — подключённые по приглашению) |

Нативный «Redis» от Vercel (только `REDIS_URL`, без REST) не подходит — нужен Upstash.

## Эндпоинты

| Адрес | Назначение |
|---|---|
| `GET /api/status` | что подключено; с Authorization ещё `authorized` |
| `POST /api/orders` | заказ с сайта: проверка, пересчёт цен, проверка остатка (409), номер `5S-1001…`, сохранение, уведомление в Telegram, ссылка «Следить в Telegram» |
| `GET/PATCH/DELETE /api/orders` | админка: список, статус/оплата (уведомляет покупателя, двигает остатки при отмене), удалить все |
| `GET /api/products` | каталог или `{products:null}` (тогда сайт берёт data.js); кэш CDN 10 с |
| `PUT/PATCH/DELETE/POST /api/products` | админка: заменить весь каталог (таблица), изменить товар, удалить, `reset` |
| `GET/POST /api/image` | фото из админки (до 600 КБ, ключ — имя файла без расширения) |
| `GET/POST /api/telegram` | админка: `enable` (webhook, команды, кнопка «Магазин»), `invite`, `test`, `disconnect` |
| `POST /api/bot` | webhook Telegram, проверка `X-Telegram-Bot-Api-Secret-Token` (секрет выводится из токена) |

Ответы с ошибками: `{ error: код, message: текст для человека }`. 4xx-сообщения
показываются покупателю как есть — пиши их понятными.

## Ключи Redis

```
fs:orders (hash номер → JSON)      fs:orders:seq           fs:order:track:<token>
fs:products (hash id → JSON)       fs:products:meta        (version, count, updatedAt)
fs:images, fs:images:v (hash стем → {type,data} / версия)
fs:telegram:chats (JSON сотрудников)  fs:tg:bot (имя бота, сутки)
fs:tg:invite:<код> (15 мин)  fs:tg:relay:<staff>:<msgId> → покупатель (60 дней)
fs:tg:last:<staff> → последний спросивший (12 ч)  fs:tg:name:<chat>  fs:tg:ack:<chat>
fs:tg:orders:<chat> (set номеров)  fs:rl:<ключ> (лимиты: 8 заказов / 10 мин с IP, 20 сообщений боту / 10 мин)
```

## Правила сервера

- Никаких npm-зависимостей: CommonJS, `fetch`, `crypto`, `vm`. Функциям, которые
  читают каталог из `assets/js/*.js` через `vm`, нужен `includeFiles` в vercel.json.
- Не доверять браузеру: цены, суммы, доставка, тестовый флаг (только с паролем),
  данные мини-приложения (HMAC-подпись `initData`, срок 7 дней).
- Обработчик бота всегда отвечает 200, иначе Telegram повторяет сообщение.
- Заказ не должен потеряться: достаточно, чтобы сработало хранилище ИЛИ Telegram;
  если ни то ни другое — 502 и понятная ошибка покупателю.
- Скрытая ловушка для ботов в форме: поле `website`.

## Telegram-бот (один на всех)

- Покупатель: `/start` → меню (Открыть магазин [web_app], Мои заказы, Консультация,
  Контакты); кнопка меню «Магазин» открывает сайт внутри Telegram; `/start o_<token>`
  привязывает заказ; смена статуса/оплаты в админке → сообщение покупателю.
- Консультация: сообщение покупателя → всем сотрудникам с `force_reply`;
  ответ сотрудника (reply или обычное сообщение в личке — последнему спросившему)
  → покупателю от «Консультант 5th SENSE», сотруднику «✓ Отправлено покупателю …».
- Сотрудники — только по одноразовым ссылкам из админки (`/start staff_<код>`,
  для групп `startgroup`); в группах бот видит только команды и ответы на себя.

## Каталог и остатки

- Пока каталог ни разу не сохраняли — источник `data.js`, остатки не ведутся.
- Первая правка из админки или загрузка таблицы переносит каталог в Redis; дальше
  заказ списывает остаток, отмена возвращает, сверх остатка — 409.
- `server/products.js` `normalize()` — единственное место, где решается, какие поля
  товара допустимы; при добавлении нового поля товара добавь его туда, иначе
  сервер его молча отбросит.
